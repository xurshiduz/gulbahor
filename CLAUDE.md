# Gulbahor

Kiyim savdosi uchun ERP. Biznes talablari, qarorlar va bosqichlar `docs/REJA.md` da; Billz tahlili va undan keyingi ish tartibi (kassa to'lovi, narx turlari, mijozlar, aksiyalar, dinamik valyuta, menyu) — `docs/KEYINGI-REJA.md` da; Billz'da nima borligining to'liq ro'yxati — `docs/BILLZ-TAHLIL.md` da. Kod yozishdan oldin tegishli bo'limini o'qing: u yerda nima qilinishi va nima uchun qilinmasligi yozilgan.

## Muloqot va kod uslubi

- Foydalanuvchi bilan o'zbek tilida. Kod, identifikatorlar va commit xabarlari ingliz tilida. Foydalanuvchiga ko'rinadigan hamma matn o'zbek va rus tilida (`web/src/i18n/uz.ts`, `ru.ts`); server xato xabarlari hozircha faqat o'zbekcha.
- Izoh kam: faqat kod o'zi ayta olmaydigan sababni yozadi.
- Prettier: nuqta-vergulsiz, bitta qo'shtirnoq, 120 ustun. **Foydalanuvchiga ko'rinadigan o'zbekcha matnda o‘ va g‘ harflari `‘` (U+2018) bilan, tutuq belgisi va chet so'zga qo'shimcha (`ma’lumot`, `PIN’ni`, `Excel’ga`) `’` (U+2019) bilan yoziladi — oddiy `'` emas** (foydalanuvchi talabi, 2026-10-06): `so‘m`, `to‘lov`, `yo‘q`, `bog‘lanadi`. Bu `i18n/uz.ts`, core'dagi yorliq va xato matnlari, server xato xabarlari va testlardagi kutilgan matnlarga tegishli. Istisno: (1) printerga ketadigan etiketka — `core/labels.ts` dagi `clean` ularni oddiy `'` ga qaytaradi (printer shriftida boshqasi yo'q); (2) agent loglari (do'kon kompyuteri konsoli); (3) yozilgan matnni o'qiydigan joylar — qidiruv kaliti (`core/text.ts`) va Excel sarlavhalari (`core/import.ts` dagi `tidy`) apostrofning hamma ko'rinishini bir xil o'qiydi, ulardagi namunalar oddiy `'` da qoladi; (4) kod izohlari, hujjatlar (`docs/`, shu fayl) va commit xabarlari. Foydalanuvchi o'zi kiritgan nomlarga tegilmaydi; tizim o'zi yozgan nomlar (rol, xarajat turi, tizim hisoblari) `1790000027000-uzbek-letters` migratsiyasi bilan o'tkazilgan. Ko'p faylni birdan o'tkazish kerak bo'lsa, qoida: o/g dan keyingi `'` → `‘`, ikki harf orasidagi boshqa `'` → `’`.
- Tugatishdan oldin: `npm run typecheck`, `npm run lint`, `npm test`.

## Tuzilishi

- `packages/core` — bog'liqliksiz (faqat zod) umumiy qoidalar: `money.ts` (minor birlik, `allocate`, `convert`), `expression.ts` va `amount.ts` (kiritilgan summani o'qish), `date.ts`, `phone.ts`, `text.ts` (qidiruv kaliti), `access.ts` (modullar, ruxsatlar, tayyor rollar), `schemas.ts` (API shartnomalari va DTO tiplar), `catalog.ts` (tovar: shartnomalar, shtrix-kod, variant kombinatsiyalari), `purchasing.ts` (hamkor, kirim, qoldiq shartnomalari va `costReceipt` — tannarx hisobi), `import.ts` (Excel ustunlarini tanish va qatorni o'qish), `stockdocs.ts` (ko'chirish, hisobdan chiqarish, inventarizatsiya shartnomalari), `labels.ts` (EPC, etiketkaning ZPL buyruqlari, printer va agent shartnomalari), `pricing.ts` (ustama qoidasini tanlash, narxni ommaviy o'zgartirish shartnomalari; yaxlitlash — `money.ts` dagi `roundPrice`), `settlements.ts` (hamkor to'lovi shartnomalari; `settledFor` — hisobga tushgan pul hamkor hisobidan qancha yopishi, `amountFor` — teskarisi; `settleLine(summa, hisobValyutasi, yopiladiganValyuta, kunKursi, kelishilgan?)` — qatorning qiymati: kun kursida yoki kelishilgan summa bilan, `fx` — ikkalasining farqi so'mda; `rateGap` va `straysFromRate` — kelishilgan summa kun kursidan qancha uzoq), `pos.ts` (hisoblar, kurs, smena va sotuv shartnomalari; `saleTotals` — chek summasi va chegirmani qatorlarga bo'lish, `settle` — aralash to'lov, qoldiq va qaytim; `returnShare` — qaytgan tovarning qiymati, `settleRefund` — qaytariladigan pul). Server uni yig'ilgan holda (`dist`), web manbadan (`vite` alias) oladi. **Core o'zgarsa, server uchun `npm run build:core` kerak** (`dev:server` buni o'zi qiladi).
- `server/src` — `modules/<nom>/` ichida controller, service, module. `database/` — entity'lar (faqat tip uchun), migratsiyalar, `Db`.
- `web/src` — `app/` (qobiq, router, navigatsiya, Ctrl+Q qidiruvi), `components/ui/` (umumiy komponentlar), `features/<nom>/` (sahifalar), `lib/` (api, hotkeys, scanner, realtime).
- `agent` — do'kon kompyuterida ishlaydigan dastur (`agent/README.md`): printerga ish yetkazadi (`printer.ts`), RFID o'quvchilarni eshitadi (`readers.ts`: `openLineReader` — har qatorda bitta EPC keladigan TCP aloqa, `Guard` — darvoza qarori, `Presence` — stolga qo'yilgan dona bir marta aytiladi). `agent/bridge/` — Chainway R3 va UR4 ni shu ko'rinishga keltiradigan Java ko'prigi (ishlab chiqaruvchining `ReaderAPI` kutubxonasi bilan; SDK fayllari `bridge/lib/` da, git'ga tushmaydi). **Ko'prik yig'iladi (JDK 21, `bridge/build.cmd`), lekin uskunada sinalmagan**: uskuna kelganda `bridge/README.md` dagi ro'yxat bo'yicha tekshiriladi. Core'ga bog'liq emas: yolg'iz o'zi o'rnatiladi. Server testlari uning yig'ilgan holini ishlatadi (`npm run build:agent`).

## Server qoidalari

- **Ma'lumotga faqat `Db.tenant(orgId, ({ em, afterCommit }) => ...)` orqali kiriladi.** U tranzaksiya ochadi va `app.org_id` ni qo'yadi; RLS qolganini qiladi. Tashkilot hali noma'lum bo'lgan joylar (login, refresh, biznes yaratish) uchun `Db.system`. Repository'ni to'g'ridan-to'g'ri inject qilib ishlatmang: tranzaksiyadan tashqarida u hech narsa ko'rmaydi.
- Yangi jadval: `org_id` ustuni, migratsiyada RLS siyosati (`migrations/rls.ts` dagi `tenantPolicy(jadval)`), entity `database/entities.ts` ga, migratsiya `migrations/index.ts` ga. Migratsiya ichida mavjud bizneslar uchun ma'lumot yozilsa, `app.bypass_rls` yoqiladi va oxirida o'chiriladi (`1790000001000-catalog.ts` ga qarang).
- Xususiyat qiymatlarini birlashtirish (`AttributesService.mergeValue`, `POST /attributes/values/:id/merge { intoId }`): bitta rang ikki xil yozilgan bo'lsa ("Chorniy", "Qora"), variantlar qolgan qiymatga o'tadi, ikkinchisi o'chadi va tovarlar qayta indekslanadi. Bitta modelda ikkalasi ham bir xil kombinatsiyada bo'lsa, rad etiladi (`VALUES_OVERLAP`). Hozircha ekrani yo'q: faqat API.
- Ketma-ket raqamlar (artikul, ichki shtrix-kod, keyin hujjat raqamlari): `modules/catalog/counters.ts` dagi `nextNumbers(em, orgId, kalit, soni)`.
- Bitta tranzaksiyada so'rovlar ketma-ket yuboriladi: `Promise.all` bilan parallel yuborilmaydi (bitta ulanish).
- Har o'zgarish o'sha tranzaksiyada `AuditService.record` bilan tarixga yoziladi (`diff()` bilan), commit'dan keyin `RealtimeService.changed(orgId, ['resurs'])` chaqiriladi. Resurs nomi web'dagi query key'ning birinchi elementi bilan bir xil bo'lishi shart.
- Ruxsat: controller'da `@Can('guruh.amal')`, modul: `@RequireModule('kalit')`. Ruxsat yoki modul qo'shilsa — `packages/core/src/access.ts`.
- Kiruvchi ma'lumot `zod(schema)` pipe bilan tekshiriladi, sxema `core/schemas.ts` yoki `core/catalog.ts` da. Xatolar `AppError` orqali: `{ error: { code, message, fields? } }`.
- Ruxsat yoki sessiyaga ta'sir qiladigan o'zgarishdan keyin `ActorService.invalidate()`.
- Pul: faqat butun minor birlik va `core/money.ts` funksiyalari. Taqsimlash — `allocate` (og'irliklar butun son bo'lsa `allocateExact`). Float bilan hisob yo'q. `CurrencyCode` (UZS, USD) — hozircha pul hisoblari, narx va kassa shu ikkisida; `AnyCurrency` — tizim biladigan hamma valyuta (16 ta, `CURRENCIES` katalogi: qo'lda yaratilmaydi, yangisi shu yerga bitta qator).
- **Qoldiq — daftar.** Miqdor va qiymat faqat `StockService.apply(em, orgId, actorId, movements)` orqali o'zgaradi: u `stock_movements` ga yozadi (o'zgarmas) va `stock_balances` ni shu tranzaksiyada suradi. Balansni to'g'ridan-to'g'ri o'zgartirmang. Yangi harakat turi qo'shilsa — `stock_movements_kind` cheklovi va `StockMovementKind`.
- Hujjat (kirim va keyingilari): qoralama → o'tkazilgan → bekor qilingan. O'tkazilgan hujjat tahrirlanmaydi; tuzatish — bekor qilib nusxa olish yoki maxsus amal (kirimda `updateExpenses`). Hujjat o'tkazishdan oldin `FOR UPDATE` bilan qulflanadi.
- Chiqim doim FIFO: `StockService.pick` (yoki `pickBatches`) eng eski partiyadan boshlab oladi va qatorlarni qulflaydi; hujjat qaysi partiyadan nechta olganini o'zida saqlaydi (`stock_document_items`), bekor qilish aynan shularni qaytaradi.
- "Yo'lda" — har biznesning ko'rinmas joyi (`locations.kind = 'transit'`, `StockService.transit`). Jo'natilgan ko'chirish tovarni shu yerga suradi, qabul u yerdan oladi. U joylar ro'yxatida chiqmaydi (`LocationsService` dagi `REAL_PLACE`) va unga kirim qilib bo'lmaydi.
- **RFID o'quvchilar ham agent orqali** (`modules/labels/readers.service.ts`, `readers`, `gate_events`; shartnomalar `core/readers.ts`). Ikki turi bor: `desk` — kassa stolidagi o'quvchi (kassaga biriktiriladi, bitta kassaga bitta), `gate` — do'kon eshigidagi darvoza. Agent ulanganda server unga o'quvchilar ro'yxatini (`readers`) yuboradi. Kassa o'quvchisi o'qigan donani agent `tag` bilan aytadi, server uni o'sha kassaning ekraniga `RealtimeService.event(orgId, 'reader.tag', …)` bilan uzatadi va kassa uni skanerlangandek qidiradi. **Darvoza qarorini agent o'zi chiqaradi**: sotilmagan donalar (`GUARDED_UNIT_STATUSES`: `ready`, `in_stock`) ro'yxatini `units` so'rovi bilan oladi (to'liq — sahifalab, keyin faqat `since` dan beri o'zgarganlari; `rfid_units.updated_at` ni trigger yuritadi), har o'zgarishdan keyin server `units.changed` deb turtadi (`RealtimeService.onChanged`). Signal chalgach agent `alarm` yuboradi; server donani qayta tekshiradi (sotilgan bo'lsa yozmaydi), `gate_events` ga yozadi va ekranlarga `gate.alarm` yuboradi. Agentning xabarlari kaliti tekshirilguncha kutadi (`socket.data.known`): aloqa uzilgan paytda yig'ilgan signal yo'qolmaydi. Nest `@SubscribeMessage` `null` qaytarsa javob yuborilmaydi — doim biror narsa qaytariladi.
- **Server printerga o'zi ulanmaydi.** Tizim domenda, printer do'kon tarmog'ida turadi. Chop etish — `print_jobs` ga ish yozish (`PrintQueueService.enqueueIn`) va commit'dan keyin `dispatch(orgId, agentId)`; ishni do'kon agenti `/agent` socket'i orqali oladi. Agent faqat lokal tarmoq manzillariga yuboradi (`isLocalHost` — core'da va agentning o'zida).
- RFID dona (`rfid_units`): kodi (`EPC_PREFIX` + hamma biznes uchun umumiy `rfid_epc_serial` ketma-ketligi) bir marta beriladi va o'zgarmaydi. Kirim donalari kirim bilan birga yuradi: `modules/labels/units.ts` dagi `settleReceiptUnits` (o'tkazilganda), `voidReceiptUnits` (bekor qilinganda yoki o'chirilganda).
- Narxni ommaviy o'zgartirish — `PricingService.reprice`: `dryRun` bilan faqat hisoblaydi, usiz yozadi va `price_revisions` ga eski-yangi narxlarni saqlaydi (`revert` shulardan qaytaradi). Modelning o'z narxi o'zgaradi, alohida o'lcham yoki do'kon narxi unga mutanosib suriladi.
- Ko'chirish, hisobdan chiqarish va inventarizatsiya bitta jadvalda (`stock_documents.kind`) va bitta modulda (`modules/stockdocs`). Ruxsat hujjat turiga bog'liq bo'lgani uchun controller'da emas, servisda tekshiriladi (`need(actor, kind, 'view' | 'manage' | 'post')`).
- **Pul ham daftar.** Har hisobning (`accounts`: kassaning so'm va dollar naqdi, karta, terminal, seyf, bank, ichki hisoblar) qoldig'i faqat `LedgerService.post(em, actor, head, postings)` orqali o'zgaradi. Yozuv ikki tomonlama: qatorlarning so'mdagi qiymati (`base`) yig'indisi nol bo'lishi shart — buni servis ham, bazadagi kechiktirilgan trigger ham tekshiradi. Dollar hisobda dollar bo'lib turadi (`amount`), so'mdagi qiymati o'sha kungi kurs bilan yoziladi. Bekor qilish — `LedgerService.reverse`. Ichki hisoblar (`sales`, `rounding`, `fx`, `cash_diff`, `opening`) `systemAccount` bilan olinadi.
- Sotuv (`modules/pos/sales.service.ts`): narxni server o'zi oladi, kassa yuborgan `total` mos kelmasa `PRICE_CHANGED` qaytadi (kassa `/pos/items` bilan savatni yangilaydi). `clientKey` — bir sotuv ikki marta yuborilsa ham bir marta yoziladi. Qaytim ikki valyutada yuritiladi (`sales.change_uzs`, `change_usd`): mijoz dollarda so'rasa (`changeCurrency: 'USD'`), `settle` butun dollarni dollarda, qolganini so'mda beradi; so'mdagi qismi sozlamadagi qadamgacha yaxlitlanadi va farq `rounding` hisobiga yoziladi. Sotuv smenani `FOR UPDATE` bilan ushlaydi; chek faqat smenasi ochiq turganda bekor qilinadi. Smena yopilishi ko'r-ko'rona: kutilgan summa va farq faqat `sales.shifts` ruxsati bor odamga va faqat yopilgandan keyin ko'rinadi.
- Qaytarish va almashtirish (`modules/pos/returns.service.ts`): tovar faqat sotilgan chekiga qarshi va qatorda qolganidan ko'p bo'lmagan miqdorda qaytadi (`sale_lines.returned_qty`, `returned_total`); qiymati — o'sha qatorga to'langan pul (`returnShare`, oxirgi dona qoldiqni oladi). Sotuv olgan partiya bo'laklari (`sale_items.returned_*`) o'z tannarxi bilan qoldiqqa qaytadi, RFID dona yana `in_stock` bo'ladi. Pul to'langan usulda qaytadi: har usul uchun chegara (`caps`) — o'sha usulda to'langanidan avval qaytarilgani ayirilgan; `pos.return_any` ruxsati bu chegarani va qaytarish muddatini (`returnDays`) chetlab o'tadi. Almashtirish — bitta tranzaksiya: qaytarish + yangi sotuv (`SalesService.createIn(em, actor, input, credit)`), qaytgan tovar qiymati yangi chekka `exchange` usuli bilan to'lov bo'lib o'tadi (`exchange` ichki hisobi orqali, u har almashtirishdan keyin nolga qaytadi). Qaytarilgan yoki almashtirish bilan to'langan chek bekor qilinmaydi. Qaytarish tahrirlanmaydi va bekor qilinmaydi.
- Pul o'tkazmasi (`modules/money/transfers.service.ts`, `money_transfers`): pul bir hisobdan boshqasiga ikki kishi bilan o'tadi. Yuborilganda u hisobdan darhol chiqib, `transit` ichki hisobida turadi; qabul qiluvchi tasdiqlagandagina ikkinchi hisobga kiradi (yuborilgandagi so'm qiymati bilan). Rad etilsa yoki yuboruvchi qaytarib olsa, pul chiqqan hisobiga qaytadi. Yuborgan odam o'zi qabul qila olmaydi (`money.manage` bundan mustasno). Kassa naqdini smenasi ochiq kassir yoki `money.collect` egasi yuboradi; kassaga kelgan pulni smenasi ochiq kassir qabul qiladi. Hisobda yetmasa, summa aytilmasdan rad etiladi (kassir daftardagi qoldiqni bilmasligi kerak). Smena yopilishida `handovers` berilsa, sanalgan puldan shu qismi o'sha tranzaksiyada seyfga yuboriladi (`sendIn`).
- Rahbar tasdig'i (`modules/pos/approvals.service.ts`): kassir o'zi qila olmaydigan ish (chegaradan oshiq chegirma, muddati o'tgan qaytarish, pulni boshqa usulda qaytarish) so'rovga `approval: { userId, pin }` qo'shilsa o'tadi — ruxsati bor xodim kassir ekranida o'z PIN kodini teradi. PIN amalning tranzaksiyasidan **oldin**, alohida tekshiriladi (`verify`): noto'g'ri urinish amal bajarilmasa ham sanaladi, 5 ta xatodan keyin PIN o'chiriladi. Hech kim o'ziga o'zi tasdiq bera olmaydi. Tasdiq faqat kerak bo'lgan joyda yoziladi (`approved_by`). Token ham, saqlanadigan holat ham yo'q.
- Terminal solishtiruvi: smena yopilishida har terminalning o'z yakuniy cheki summasi kiritiladi (`shift_terminal_counts`), tizim uni shu smenada o'sha terminalga urilgan to'lovlar (qaytarilgani ayirilgan) bilan solishtiradi. Kutilgan summa va farq, naqd sanoqdagi kabi, faqat `sales.shifts` ruxsati borlarga ko'rinadi.
- Hamkor hisobi (`modules/partners/payments.service.ts`, `partner_payments`): har hamkorning bitta hisobi bor (`accounts.kind = 'partner'`, `LedgerService.partnerAccount`), so'mda yoki dollarda; qoldiq — hamkor bizga qancha qarzdorligi (manfiy bo'lsa biz qarzdormiz). Valyuta hisobga birinchi yozuv tushgach o'zgarmaydi. To'lov bir nechta qatordan iborat: har qator pulning o'z hisobiga (kassa naqdi, seyf, karta, bank) o'z valyutasida kiradi yoki chiqadi, hamkor hisobidan yopiladigan summani server kun kursidan o'zi hisoblaydi — qatorda **kelishilgan summa** (`settled`) kelmagan bo'lsa. Kelishilgan summa ("100 dollarni 1 200 000 deb ol") kelsa, hamkor hisobi aynan shu summaga suriladi, pul hisobi esa **doim kun kursida** baholanadi; farq `fx` ichki hisobiga tushadi va qatorda saqlanadi (`partner_payment_lines.fx`, `money_op_lines.fx`, `debt_payment_lines.fx`; + biznes foydasi). Qoida bitta joyda: `modules/money/agreed.ts` dagi `valueLine` (hamkor to'lovi, xarajat va kirim, mijoz qarzi — uchala servis shuni chaqiradi) va `rateLimit`: kun kursidan `OrgSettings.maxRateLossPercent` dan ko'p uzoqlashgan summa (ikkala tomonga) faqat `money.rates` egasidan qabul qilinadi, aks holda `lines.N.settled` xatosi. To'lovning jami `settled` i ekran ko'rsatganiga mos kelmasa `RATE_CHANGED` qaytadi. Forma uchun hisoblar ro'yxati (`GET /partner-payments/accounts`) har hisob hozir pul o'tkaza olishini ham aytadi (`open`: kassa naqdi faqat smenasi ochiq bo'lsa). Kurs — kunlik; qatorda kurs yuborilmaydi (ekrandagi kurs maydoni faqat yopiladigan summani hisoblab beradi, serverga kelishilgan summa bo'lib boradi). So'm dollar hisobni yopganda sentgacha yaxlitlashdan qolgan tiyin `fx` hisobiga yoziladi. Kassa naqdidan o'tgan qator smenaga bog'lanadi (ochiq smena shart) va smena hisobotida ko'rinadi; smena yopilgach bunday to'lov bekor qilinmaydi (`SHIFT_CLOSED`). Bekor qilish — `LedgerService.reverse`, hujjat daftarda qoladi. Boshlang'ich qoldiq `opening` ichki hisobiga qarshi yoziladi (`partners.adjust`). Kirim o'tkazilganda har yetkazib beruvchiga (qatorning `supplierId` si, bo'lmasa hujjatniki) tovar qiymati (xarajatsiz, kirim kursida) uning hisobiga `purchases` ichki hisobiga qarshi yoziladi (`ReceiptsService.owe`), kirim bekor qilinganda qaytariladi; yetkazib beruvchisiz tovar yozilmaydi. Hisob-kitobda bunday qator `source: 'receipt'`. Qarzni ko'rish — `partners.debts`, to'lov — `partners.pay`; ruxsatsiz xodimga `PartnerDto.balance` `null` keladi.
- Biznes sozlamasi (`OrgSettings`) so'rovda yuborilmasa o'zgarmaydi: `orgUpdateSchema` da yangi maydonlar `optional`, standart qiymat o'qishda (`DEFAULT_ORG_SETTINGS`) qo'shiladi.
- Bir tranzaksiyada boshqa modul ishini bajarish kerak bo'lsa, o'sha servisning `...In(em, ...)` metodi ishlatiladi (`ProductsService.createIn`, `ReceiptsService.createIn`). Sinov rejimi (import `dryRun`) — haqiqiy ishni bajarib, tranzaksiyani qaytarish.

## Web qoidalari

- So'rovlar `lib/api.ts` orqali, holat TanStack Query'da. Query key resurs nomi bilan boshlanadi (`['users', 'list', filters]`).
- Ro'yxat sahifasi: `DataTable` + manzildagi holat (`lib/list-search.ts`, route'da `validateSearch`). Forma: `Form` + `zodSubmit(form, schema, ...)` + `applyServerErrors`; so'rov forma maydonlaridan boshqacha tuzilsa — `zodCheck(form, schema, data)`.
- `Form` ichida Enter keyingi maydonga o'tadi. Kam ishlatiladigan boshqaruv elementi `data-enter-skip` ichiga qo'yilsa, Enter uni chetlab o'tadi (Tab bilan baribir yetiladi).
- Inputlar: summa — `MoneyInput`, miqdor — `NumberInput`, telefon — `PhoneInput`, PIN — `PinInput`, parol — `PasswordInput` ("ko'z" bilan), sana — `DateInput`, tanlash — `Combobox`, kodlar ro'yxati (shtrix-kod) — `TagInput`, rang × o'lcham bo'yicha miqdor — `QtyMatrix`, tovar qidirish (serverda) — `features/catalog/product-picker`. Oddiy `<input type="number">` ishlatilmaydi.
- `Combobox` da "Yangi: «…»" qatori hech qachon o'zi tanlanmaydi: xato yozilgan matn yoki skanerlangan kod Enter bilan yangi yozuv yaratib qo'ymasligi kerak. Unga ↓ bilan ataylab tushiladi. Ko'p tanlovda matn bo'sh bo'lsa, Enter "tugatdim" degani va keyingi maydonga o'tkazadi.
- `useHotkey('escape', ...)` ustida ochiq oyna yoki ro'yxat bo'lsa ishlamaydi: Esc avval o'shani yopadi.
- Tugmalar: `useHotkey(combo, handler, { label, group })`. `label` berilsa, F1 oynasida ko'rinadi.
- Yangi sahifa: `app/router.tsx` (route), `app/navigation.ts` (menyu, ruxsat, modul), `i18n/uz.ts` va `ru.ts`. Menyu bandining `permission` i ro'yxat bo'lsa, ulardan bittasi yetarli.
- **Sahifa ikki xil bo'ladi.** Odatda `Page` oynaning balandligiga teng va ichidagi uzun narsa (ro'yxat, hujjat formasi) o'zi aylanadi.
